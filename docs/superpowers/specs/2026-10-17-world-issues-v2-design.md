# 오늘의 세계 이슈판 v2 설계

작성일: 2026-10-17

## 목표

지금 혼자 보는 한 페이지 사이트를 **모르는 사람들이 검색과 공유로 찾아오는 다국어 사이트**로 바꾸고, 광고와 후원으로 수익을 낸다.

성공 기준:
- 4개 언어(ko/en/ja/zh)로 모든 페이지가 만들어지고, 오른쪽 위에서 언어를 바꿀 수 있다.
- 이슈마다 검색에 걸리는 개별 페이지가 생기고, 날짜·나라·분야별 페이지가 매일 쌓인다.
- 맥북이 꺼져 있어도 매일 한국 시간 06:00에 갱신된다.
- 구글 정책을 지키는 방식으로 검색 유입을 늘린다. 키워드 도배, 퍼오기, 가짜 트래픽, 얇은 페이지 대량 생산은 하지 않는다.

## 전체 작업 순서

| 순서 | 덩어리 | 내용 |
|---|---|---|
| 1 | 사이트 새로 짜기 | 이 문서의 본문. 다국어, 정적 페이지 생성, 검색 장치 |
| 2 | 사이트 이전과 자동 갱신 | 도메인 구입, Cloudflare Pages 이전, Claude 클라우드 예약 작업으로 매일 06:00 KST 갱신, IndexNow, 검색엔진 등록 안내 |
| 3 | 수익 | 후원 버튼(바로), 구글 애드센스(페이지와 방문자가 쌓인 뒤 신청) |
| 4 | 크롬 확장 | 툴바 버튼(오늘의 인기 이슈 팝업, 새 이슈 숫자 표시) + 설정에서 켜는 새 탭 화면. `feed.json`을 읽는다. 웹스토어 등록비 5달러 |

각 덩어리는 설계 → 확인 → 구현 순서로 따로 진행한다. 아래 내용은 1번 덩어리의 설계다. 2~4번과 이어지는 부분만 함께 적었다.

## 1. 페이지 구성과 주소

갱신할 때마다 완성된 HTML 페이지를 미리 만들어 `site/` 폴더에 둔다. 페이지는 처음부터 글자로 완성돼 있어야 한다. 지금의 Apple 스타일 디자인, 나라 탭, 분야 필터는 그대로 살리고, 자바스크립트는 탭과 필터 같은 편의 기능에만 쓴다.

| 페이지 | 주소 | 내용 |
|---|---|---|
| 첫 화면 | `/{lang}/` | 최신 이슈판. 지금 화면과 같은 구성 |
| 이슈 개별 | `/{lang}/issue/{id}/` | 이슈 하나의 상세 페이지 |
| 날짜별 기록 | `/{lang}/{YYYY-MM-DD}/` | 그날(한국 날짜) 갱신분 전체 |
| 나라별 모음 | `/{lang}/{country}/` | 그 나라 이슈를 최신순으로 쌓는다 |
| 분야별 모음 | `/{lang}/{field}/` | 분야별 이슈를 최신순으로 쌓는다 |
| 깃허브 트렌딩 | `/{lang}/github/`, `/{lang}/github/{YYYY-MM-DD}/` | 지금의 깃허브 탭 |
| 루트 | `/` | 영어판 첫 화면과 같은 내용. 브라우저 언어가 ko/ja/zh면 해당 언어로 가자고 안내한다(강제 이동하지 않음) |

- `lang`: `ko`, `en`, `ja`, `zh`(간체)
- `country`: `korea`, `usa`, `japan`, `china`, `world`(지금의 '유럽 외', etc)
- `field`: `tech`, `politics`, `culture`, `incidents`
- 모음 페이지는 목록이 길어지면 페이지를 나눈다(`/page/2/`). 한 페이지에 30개씩 보여 준다.

**언어 전환**: 오른쪽 위 선택 메뉴에서 고르면 같은 페이지의 다른 언어판으로 이동한다. 고른 언어는 브라우저에 기억해 둔다. 기억이 안 되는 환경에서도 페이지는 정상적으로 보여야 한다.

**이슈 개별 페이지**
- 평균 5.0 이상인 이슈는 모두 만든다. 이슈판 선정 기준도 5.0이다.
- 본문은 네 단락이다: 무슨 일인지 / 왜 화제인지 / 반응 / 앞으로 볼 점.
- 출처, SNS 링크, 점수, 같은 나라·분야의 관련 이슈 링크(최대 6개)를 붙인다.
- 네 단락을 못 채운 이슈는 개별 페이지를 만들지 않는다. 이슈판에는 요약 카드로만 나온다.
- 다음 갱신에 같은 이슈가 이어지면 같은 ID를 쓰고, 기존 페이지를 고친다. "처음 나온 날"과 "마지막 갱신"을 함께 보여 준다.

**광고·후원 자리**: 첫 화면, 이슈 개별 페이지, 모음 페이지에 비어 있는 자리만 마련한다. 실제 내용은 3번 덩어리에서 채운다. 자리가 비어 있을 때는 아무것도 보이지 않아야 한다.

## 2. 갱신 시각 표시

갱신은 하루 한 번, 한국 시간 06:00 기준이다.

- 나라 탭과 나라별 페이지에는 그 나라 현지 시각으로 갱신 시각을 보여 준다.
  - 한국: KST
  - 미국: 뉴욕(ET), LA(PT)
  - 일본: JST
  - 중국: CST(UTC+8)
  - 유럽 외: 파리(CET/CEST), 런던
  - 서머타임은 시간대 데이터베이스로 자동 반영한다.
- 화면 맨 위에는 보는 사람의 시간대 기준 갱신 시각과 "N시간 전" 표시를 보여 준다. 이 부분만 브라우저에서 계산하고, 계산이 안 되면 KST 시각을 보여 준다.
- 표시 문구는 고른 언어를 따른다. 예: 영어 "Updated Oct 16, 5:00 PM ET".

## 3. 데이터

`data.js`를 아래 JSON 파일들로 바꾼다.

**`data/latest.json`**: 이번 갱신분

```json
{
  "updated": "2026-10-17T06:00:00+09:00",
  "countries": {
    "korea": {
      "items": [ ... ],
      "cut": [{"ko": "...", "en": "...", "ja": "...", "zh": "..."}]
    }
  },
  "github": {"date": "2026-10-17", "items": [ ... ]}
}
```

이슈 항목:

```json
{
  "id": "kospi-rebound-oct-2026",
  "field": "tech",
  "scores": [8, 8, 9, 6],
  "youth": false,
  "links": [{"p": "naver", "q": "코스피 반등"}],
  "source": {"name": "Korea Herald 10/16", "url": "https://..."},
  "text": {
    "ko": {"title": "...", "summary": "...", "body": ["...", "...", "...", "..."]},
    "en": { ... }, "ja": { ... }, "zh": { ... }
  }
}
```

- `id`: 영어 소문자, 숫자, 하이픈만 쓴다. 60자 이하. 전체 기간에서 겹치지 않아야 한다.
- `links`의 `p`는 플랫폼 키(ig, naver, x, rd, th, tt, wb)다. 링크 주소는 만들기 단계에서 지금의 `L` 규칙대로 만든다.
- 깃허브 항목은 저장소, 언어, 전체 별, 오늘 받은 별, 언어별 설명을 담는다.
- 나라별 분석 플랫폼 목록은 매일 바뀌지 않으므로 `gen/config.py`에 둔다.

**`data/issues/{id}.json`**: 이슈별 누적 기록. 최신 항목 내용, `first_seen`, `last_updated`, 나온 날짜 목록을 담는다. 개별 페이지와 모음 페이지는 이 파일들로 만든다.

**`data/archive/{YYYY-MM-DD}.json`**: 그날 갱신분 원본. 날짜별 기록 페이지를 만들 때 쓴다.

**기존 데이터**: 지금까지의 4회분은 한국어 요약만 있어서 옮기지 않는다. 새 구조의 첫 갱신부터 쌓는다. `history/`와 `data.js`는 지우지 않고 남겨 둔다.

## 4. 갱신 흐름

자동 실행 프롬프트를 두 단계로 나눈다.

1. **조사 + 한국어 작성** (`refresh-prompt.md` 고침)
   - 웹 검색으로 나라별 이슈를 모으고, 점수를 매기고, 한국어로 제목·요약·본문 네 단락을 쓴다.
   - `data/issues/`를 보고, 이전 이슈와 같은 이슈면 기존 ID를 쓴다.
   - 깃허브 트렌딩 상위 10개를 받는다.
   - 결과를 `data/draft.json`(한국어만)으로 쓴다.
2. **번역** (`translate-prompt.md` 새로 만듦)
   - `data/draft.json`의 한국어를 en/ja/zh로 옮겨 `data/latest.json`을 쓴다.
   - 번역본 검사에 실패하면 같은 실행 안에서 번역을 한 번 더 한다(하루 한 번 갱신이라 다음 실행까지 미루지 않는다). 그래도 실패하면 이전 `latest.json`으로 되돌린다.

그 다음 `build.py`가 검사하고, 통과하면 `issues/`, `archive/`를 갱신하고 `site/`를 만든다. 실패하면 이번 회차 결과를 버리고 이전 사이트를 그대로 둔다.

갱신을 어디서 돌릴지(Claude 클라우드 예약 작업)와 올리는 방법은 2번 덩어리에서 정한다. 그 전까지는 지금의 맥북 launchd를 쓰되, 실행 시각만 06:00 하루 한 번으로 바꾼다.

## 5. 검사 (`build.py`)

데이터가 아래 중 하나라도 어기면 멈추고 무엇이 틀렸는지 한국어로 출력한다.

- `updated`가 있고 시간대가 들어 있다.
- 나라 5곳 모두 항목이 1개 이상 있다.
- 항목마다 점수 4개, 평균 5.0 이상이고, 분야별 10개 이하다.
- 항목마다 `source.url`과 `links`가 1개 이상 있다.
- `id` 형식이 맞고, 이번 회차 안에서 겹치지 않는다.
- 항목마다 4개 언어 모두 `title`과 `summary`가 있다.
- 깃허브 항목이 10개다.

`body`가 네 단락이 아닌 항목은 오류로 보지 않는다. 개별 페이지만 건너뛰고, 건너뛴 목록을 출력한다.

## 6. 검색 장치

- 페이지마다 언어에 맞는 `<title>`, 설명, canonical 주소를 넣는다. 제목에 날짜와 나라를 넣는다. 예: "Oct 17, 2026 · What's trending in Japan".
- 언어별 페이지를 `hreflang`으로 서로 연결하고, `x-default`는 영어판(`/en/...`)으로 둔다. 루트(`/`)는 영어판과 같은 내용이고 canonical이 `/en/`이므로 사이트 지도에는 넣지 않는다.
- 구조 정보(JSON-LD)를 넣는다. 개별 페이지는 `NewsArticle`, 목록은 `ItemList`, 모든 페이지에 `BreadcrumbList`를 쓴다.
- `sitemap.xml`을 갱신할 때마다 새로 만든다. hreflang 연결과 마지막 수정일을 넣고, 커지면 사이트 지도 묶음(sitemap index)으로 나눈다.
- `robots.txt`를 만들고, 언어별 RSS(`/{lang}/feed.xml`)를 만든다.
- 크롬 확장용 `/feed.json`을 만든다. 최신 갱신 시각과 나라별 상위 이슈 5개(4개 언어 제목, 개별 페이지 주소)를 담는다.
- 공유 미리보기(Open Graph·X 카드) 이미지는 언어×나라 조합별로 자동으로 만든다(Pillow). 이슈별 이미지는 이번 범위에서 뺀다.
- 페이지 아래에 "AI가 공개 기사와 SNS를 바탕으로 정리했으며, 점수는 실제 언급량이 아니라 판단 값"이라고 각 언어로 밝힌다.
- 빠른 로딩을 위해 페이지별 자바스크립트를 최소로 하고, 글꼴은 언어별로 필요한 것만 불러온다.

## 7. 파일 구성

| 파일 | 역할 |
|---|---|
| `build.py` | 검사, 누적 기록 갱신, 사이트 생성의 진입점 |
| `gen/` | 페이지 종류별 생성 코드, 시간대 계산, 사이트 지도·RSS·feed 생성 |
| `gen/html.py` | 페이지 HTML 틀(템플릿 엔진 없이 파이썬 함수로 만든다) |
| `i18n/{lang}.json` | 화면 고정 문구(탭 이름, 버튼, 안내문)의 언어별 번역 |
| `static/` | `styles.css`, 탭·필터·언어 전환용 작은 스크립트 |
| `data/` | 위 3절의 데이터 |
| `site/` | 만들어진 결과물 (배포 대상) |

## 8. 확인 방법

- 일부러 틀린 데이터로 검사를 돌려 항목별로 제대로 멈추는지 확인한다. 점수 미달, 출처 없음, 언어 빠짐, ID 중복, 깃허브 9개 같은 경우다.
- 같은 ID가 다음 회차에 다시 나오면 기존 개별 페이지가 고쳐지고 새 페이지가 생기지 않는지 확인한다.
- 시간대 표시를 서머타임 전후 날짜로 확인한다.
- 만들어진 사이트를 내 컴퓨터에서 띄워서 확인한다. 4개 언어, 언어 전환, 탭·필터, 모바일 폭, 다크 모드를 본다.
- 구조 정보가 schema.org 형식에 맞는지, 사이트 지도의 주소가 모두 실제 파일과 맞는지 확인한다.
- 실제 갱신을 한 번 돌려 걸린 시간과 사용량을 기록한다. 사용량이 많으면 본문 길이를 줄인다.

## 범위 밖 (이번에 하지 않음)

- 이슈별 공유 이미지
- SNS 계정에 자동으로 글 올리기
- 댓글, 회원 기능
- 기존 4회분 데이터 옮기기
